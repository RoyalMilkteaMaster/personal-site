# QA-06：Ticket 09-r3 簡單模式的兩項輕微 UX 觀察（僅記錄，勿自動修）

來源：使用情境 QA，Snapshot 09-r3（8823，`?nebula-diag=off`），Playwright Chromium 402×681 桌面模擬（非 iPhone、非 WebKit）。
證據：`work/starlit-mobile-optimization/scroll-performance/ticket-09/qa/screens-r3/`、`qa/partial-result.md` 的 09-r3 段。
本檔不涉及白屏是否修好；r3 簡化流程尚未經使用者實際使用驗證。

## 🟡 恢復／暫停鈕小於 iOS 慣例可點區
- 情境：使用者在手機上用拇指切換「暫停／恢復」比較白屏差異，可能反覆切換多次。
- 證據：面板唯一按鈕實測 78×36 CSS px（`r3-01-open-paused.png`、`r3-05-chapter-paused.png`）；iOS HIG 慣例約 44×44pt。
- 影響：模擬環境可正常點擊；真機拇指點擊容錯較小，可能誤點到按鈕外的頁面內容（面板下方即為章節內容）。
- 判斷：有依據的風險（平台慣例），未在真機驗證。
- 改善方向：讓這顆切換鈕在手機上有足夠的可點高度，不改變面板整體高度太多即可。

## 🟡 簡單模式沒有關閉面板的入口
- 情境：使用者比較完了，只想把底部那條測試列拿掉繼續正常瀏覽。
- 證據：簡單模式只渲染狀態文字＋一顆「恢復星雲／再次暫停」；r2 的「結束並恢復」不存在（`r3-02-restored.png`）。唯一方法是自行把網址上的 `?nebula-diag=off` 刪掉重新載入。
- 影響：在 iPhone Safari 上編輯網址比按一顆鈕麻煩；使用者可能以為「恢復星雲」＝結束測試，但長條仍在。
- 判斷：需要開發者決定（也可能刻意保留，以便使用者反覆切換）。
- 改善方向：若要保留切換能力，可同時提供一個明確的結束入口，結束後回到完全正常的畫面。
