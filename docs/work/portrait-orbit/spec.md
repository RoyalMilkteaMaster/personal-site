# 人物星空開場連續繞拍規格

## 最新核准要求：開工前先讀（2026-09-10）

使用者已明確否決 v9。以下整理本任務直接指示，優先於舊版建構方式；不代表成果已驗收。完整錯誤清單見 `user-regression-checklist.md`，派工必讀 `agent-brief.md`。歷史修正與來源見 `model-alignment-amendment.md`。

- **首尾外觀是硬條件**：第一張臉部近景、最後一張正面全景，須與原版一模一樣或幾乎一模一樣。保留原圖檔案不等於保留畫面；頭部傾角、髮型輪廓、頸肩、手部、衣帶、星火位置／尺度、構圖及星點質感仍明顯不同就不通過。不得把「原畫只供參考」解讀為允許更換外觀。
- **完整 3D 同樣是硬條件**：模型是配合原畫的空間支架，必須先修正姿勢、比例、輪廓及雙手，再依真正表面 XYZ 配置星點。亮處多一些小星點，暗處有基本覆蓋；不能為了貼合首尾而挖掉側背面、使用浮動描邊、前景卡片或換人物。
- **雙手須看形狀與姿勢**：五指數量、有限座標及三角形存在都不足以通過。掌、腕、各指關節與指間空隙要自然；不得出現 v9 被否決的拉長、攤開或錯向手指。星火綁真正掌心，自轉與繞拍皆不離手。
- **背面為微仰視頭肩**：實際眼位稍低於目標，看向後腦、衣領與肩背，並符合背面參考的透視；不以只改俯仰數值或畫面裁切宣稱通過。
- **實際操作與同鏡頭比對**：每輪在可旋轉的最新模型頁檢查 0／45／90／135／180／225／270／315 度及連續 360 度；逐角度切換素模、材質模型、均勻點與最終星點，雙手另做可辨指節的近照。使用者指出 `refine.html?v=4` 的操作方式可用，但不能將該頁舊模型當最新結果。
- **首尾先驗，再驗整段**：提供相同視口的原版／候選並排與疊圖、背面參考對照、兩段完整轉場及星火完整自轉。以角色區域及部位檢查為主；不以大量背景稀釋的數值、不透明原圖覆蓋或縮小拼圖代替視覺驗收。

新增驗收 A13（對應 R02、R03、R06、U08）：首尾人物達到上述幾乎一致，且與旋轉中的同一份完整人物相連。此項與 A01–A12 同時成立才可交付；不得因其他測試通過而豁免。

本輪仍在 `work/model-trial` 隔離修正；主站整合仍受 Ticket 03 的形體及動畫驗收前置條件限制。沒有新增網站功能、替代轉場或外部生成授權。

狀態：使用者已於 2026-09-09 核准 Spec。需求與架構同日核准，本規格僅整理該範圍。核准來源為 docs/planning/requirements.md、docs/planning/architecture.md，術語依 CONTEXT.md。既有實驗尚未通過視覺驗收。

## 問題

個人網站需要鏡頭繞過同一個星點人物的開場。主頁目前使用前後人物粒子插值，後段先回正面近景再拉遠，無法呈現要求的空間連續性。固定點雲隔離實驗已能移動相機，但頭髮呈圓殼、肩頸像直筒、側面與背面的形狀／色彩對應不自然，且尚未連續接到原本完整伸手人物。

單純改速度、增加點數或通過相機數學測試，不能解決上述視覺問題。

## 目標

以既有圖片及必要的少量同人物側面參考校準固定立體星點，透過同方向、向外擴展的相機路徑，連續呈現第一姿態正面頭部近景、同姿勢背面頭肩、原本完整人物構圖。保留喜歡的原畫質感、手持物、同頁章節及星空氛圍。

## User Stories

1. 身為網站訪客，我希望鏡頭繞過的是同一個人物及星空，以便感受到連續空間，而非人物變形或換圖。
2. 身為網站擁有者，我希望正面、側面、背面都保持原角色的髮型、衣領與伸手姿勢，以便保留已喜歡的人物設計。
3. 身為網站訪客，我希望讀完開場文字後能點擊繼續或等待自動播放，並能正常重播與切換章節，以便自行控制閱讀節奏。
4. 身為網站擁有者，我希望每次修正都有可重現的角度／時間畫格與完整播放證據，以便確認缺陷確實改善，並能接續未完成的工作。

## 需求與行為

### R01 — 同一場景連續繞行

- 同一個第一姿態人物及同一片星空保持空間連續。
- 順序為正面頭部／髮絲近景，繞到同姿勢背面頭肩，再沿同方向向外到第一姿態完整人物。
- 背面略由下往上、斜側看後腦、衣領及肩膀，不拍到腰；前兩鏡不出現火種，最後全貌才出現。
- 第一段轉動 0.9 秒；兩段方向一致，移動時向外，停留時構圖穩定。第二段時長及鏡頭參數依核准構圖校準，不以現有實驗數字當作必須保留的結果。
- 不倒轉，不回舊近景再拉遠，不讓人物離場換圖，不以快轉掩蓋形體問題。

### R02 — 人物外觀與參考一致性

- 沿用第一姿態正面及背面頭肩素材作為美感基準，保留原本伸手姿勢。其他章節姿態不能作為本人物背面的替代品。
- 必要時補製少量左右側面參考；補圖先檢查同人物、髮型、衣服及姿勢一致性，再用於校準。不大量生成視角表，不把新生成圖自動視為已接受。
- 人物始終由彩色星點構成；保留髮束、臉、衣領輪廓及手指細節，不以不透明原圖代替粒子終態。
- 改善側面扁薄、圓殼頭髮、直筒肩頸、接合缺口、黑洞、物件缺損、色彩拉伸與亮度斷層。

### R03 — 固定人物與全貌接續

- 人物基礎形體和表面顏色固定，播放時由鏡頭完成繞拍；既有微浮動、正常遮擋與光照變化仍可保留。
- 第一輪候選即包含完整伸手姿態的基本形體，優先細修頭肩；整個候選仍須完成全貌檢查後才能交付。
- 後段鏡頭直接抵達第一章使用的完整人物場景；不能在結尾切回另一份正面人物或以粒子拉扯修補接合。
- 手持物維持手掌位置關係，保留自身旋轉；人物不跟著物件旋轉。

### R04 — 文字與使用者控制

- 正面及背面停留時顯示既有開場文字；文字完成後可點擊繼續，或等 3 秒自動繼續。保留既有鍵盤操作。
- 文字尚未完成時不得因繼續操作打亂階段；快速重複點擊、品牌重播、開場途中換章節皆須保持合理可用的狀態。
- 點擊左上品牌可重播；正式文案由使用者稍後提供，先使用現有暫用文案。

### R05 — 既有網站相容

- 保留同頁關於我、我的作品、聯絡資訊，三個姿態與原有內容配置。作品資料仍可擴充，不以姿態數限制作品數量。
- 章節切換沿用共用粒子池及背景星參與人物重構，文字內容同步切換；不增加先聚中央星團的中介姿態。
- 保留微浮動、少量背景星、偶爾不同步的亮度變化及手持物旋轉，不改成滿場閃爍。
- 保留縮放與版面適應、減少動態偏好，以及素材／WebGL 失敗時文字內容仍可閱讀的行為。

### R06 — 隔離修正與證據

- 先改善現有隔離實驗；形體與動畫通過視覺檢查後才整合主站，整合後再驗證網站行為。
- 每輪記錄缺陷角度／時間、畫格、觀察與修正結果；先複驗原缺陷，再檢查受影響的完整播放。
- 尚有明顯缺陷就持續在隔離候選修正，不以程式測試通過或歷史畫格宣稱完成。需要改動原畫、擴大素材範圍或更換路線時，提供具體證據再討論。
- 保留所有未提交檔案及 work/ 實驗資料；不重置、清理舊實驗或自行發布。

## 實作決策

### 資料與所有權

- 沿用既有 React／vinext／Vite／TypeScript 與自訂 WebGL。
- 人物建構邏輯讀取正面、背面及通過一致性檢查的必要側面參考，校準髮束、臉、頸、衣領、肩與身體接合，產出同一份固定基礎點雲；依修正後的表面重新計算供光照及可見性使用的法線。
- 人物 XYZ 與基礎色彩對應由建構邏輯擁有，不根據相機角度切圖或重新指派人物星點。相機、微浮動、光照、物件旋轉分工處理。
- 星點角色仍區分人物、星空及手持物，沿用現有共用粒子池與物件旋轉資料語意。

### 模組責任與公開介面

- portraitPoints／fixedBust 所在的取樣及建構接縫負責人物形體與色彩校準；不把原有浮雕深度公式當作已完成的側面重建。
- bustCamera 所在的相機接縫統一管理旋轉角度、外擴距離、注視位置與時間，提供連續相機位置和基底。
- IntroSequence 管理文字、等待、繼續、重播及階段進度，保留現有互動契約。
- AstralScene 管理素材載入、WebGL、鏡頭渲染、微浮動／閃爍及錯誤降級，繼續透過 pose、replay、advance、onIntroState 與頁面協作。
- ParticleMorph 與既有手持物幾何／旋轉維持章節重構及物件運動責任。開場不用 spiralTransition 的前後粒子插值。
- 隔離驗證頁保留角度檢查、統一色彩與角度對照能力，補足完整播放與時間軸畫格檢查所需的最小控制；實驗控制不出現在正式網站。

### Schema、API contract 與系統互動

- 沿用 Float32Array、STRIDE=13 的既有粒子介面，保留欄位在不同角色上的現有語意。
- 相機沿用 eye、right、up、back 等計算接縫。
- 開場沿用 approach、front、turn-back、back、return、done 階段語意；return 只是既有識別字，不能解讀成相機倒轉。
- 不新增 Web API、登入、多人共用狀態、資料庫或正式 Log；使用 Console 及必要的臨時排錯記錄。

### 相容、遷移與技術限制

- 保留現有程式目錄、隔離實驗、素材與建置環境，依核准架構的 Code／Data／Runtime 邊界處理，不建立大型執行環境或重新安裝建模工具。
- 正式素材及必要程式通過檢查後才納入主站，正式頁面不得依賴被忽略的實驗檔案或實驗服務。
- 開場完成後保持同一個第一姿態場景；切換章節時仍從目前可見狀態接續原粒子重構。
- 在相同瀏覽器與視窗條件下比較修改前後載入及播放效能，保留實測環境與限制；本次沒有核准固定幀率或粒子數門檻，不宣稱未測量的結果。
- 第一段 0.9 秒及文字完成後 3 秒等待為固定要求；其他鏡頭、密度與形體參數在已核准構圖和流程內校準。

## 測試決策

- 公開行為：驗證相機繞行、同場景連續性、文字及繼續操作、火種入鏡、章節切換、重播、縮放與失敗降級。
- 測試接縫：沿用人物建構純函式、相機計算、IntroSequence、ParticleMorph 及實際隔離頁／主站的瀏覽器操作。相機函式不修改輸入僅是局部證據，還需驗證渲染實際使用固定場景。
- 既有測試模式：使用 node:assert 的測試，針對實際錯誤增加最小回歸檢查；沿用 TypeScript 型別檢查與既有 build 指令，不新增不必要測試框架。
- 畫面證據：人物正背、左右側及過渡角度，單色與原圖色彩，完整播放、兩段中間畫格及全貌接合。保留可重現的角度／時間與當前候選對應，不能拿舊截圖為新實作背書。
- 不應耦合的細節：不鎖死未核准的點數、亂數樣本、相機內部函式排列或補圖版本名稱；不以固定快照或數學不變性替代視覺品質判斷。
- 驗證結果必須分清型別／數學／互動通過與視覺通過，明確記錄未檢查項目或實測限制。
